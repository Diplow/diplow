# front

Everything the browser shows, and the client's side of every call. It sits on top of the layers: `front/` → `api/` → `domains/` → `repositories/`. An import only points down, so neither a domain, nor a repository, nor the API layer can reach what the browser shows; and the front reaches the server through a server function in `src/api/`, never a repository, and of a domain only its door, pure (below). dependency-cruiser says no to both (`dependency-cruiser.config.ts`).

## Rules

- **The front imports a domain through its door only, its tests included**: its `entities/index.ts`, `operations/index.ts` and `errors.ts`, pure, so a rule, a value or a type of the domain's (Mapping's `Slot`, `directions`, `SystemTile`, `holdsNothing`) is the domain's own and never a copy; anything else of a domain, and every repository, it reaches through a server function in `src/api/`. dependency-cruiser holds it (`no-front-past-a-domains-door`; [[4-software-engineering/1-projects/1-hexframe/1-app/src/domains/CLAUDE|domains]], "The door"). A test that needs a refusal as the client receives it takes its wire form decoded (`decodeFailure`), or one of the stand-in failures named for their kind (`src/api/dev/failures.ts`).
- **Home reads the Session before it renders**, on the server too: `beforeLoad: sessionIfAny`, and draws the screen signed in or signed out, never a signed-in read signed out. The server functions behind it still start with IAM's `signedIn`; the page's read is for the user, not for security.
- **`redirect` is a path on this site, without its language prefix.** The client's Unauthenticated channel (`client/channels.ts`) writes it that way, loading home signed out, and both it and home's read of the Session untie PostHog's identity (`forget`) for a signed-out visit; home drops anything else, and `continueTo` checks it again against the page's origin before it goes there.
- **The System has one write path.** Every write to it is a mutation, a Tile form's included, so the MutationCache holds each one, pending or refused, for `useMutationState` to find while it is pending and `useSystemRefusals` to hand back once it is refused, and they reach the server in the order they were made. A form never sends its write itself: `submitWrite`, which no cache sees, is for a secret only.
- **The System is one query, and the page shows it with its pending writes on top.** The cache holds only what the server said, under the key `['system', 'read']`, never read again on focus, every Body with it; a System visited, someone else's, is a query of its own beside it, keyed by its star, read again on focus, since its Version is its owner's alone (HEX-127). It is the one Query read in two ways: the canvas throws its failure to its `ReadBoundary`, the chat beside it, `useSystem({ throwing: false })`, leaves it undefined, since a `frame` read would be a second Query and read the System, every Body, twice: the page polls the System's Version instead, the smallest read there is, and reads the System again only once it moved past the Version the cache holds (`assistant/follow.ts`), so a write the page did not make, an agent's, a Key's or another tab's, shows once the tab regains focus; `useSystem` folds every pending System write over it, in the order they were made, through Mapping's `decide` and `evolve`, so a write shows at once, a refused one stops showing without a rollback, and a read that brings someone else's change slips in under the writes still pending. An import is no Operation and folds nothing: its widget shows it on its way, and the read after it draws it. Every write reads the System again once it settles (it invalidates `['system']`, every mode), whether it succeeded or not, since a refusal such as `DirectionTaken` means the page is out of date, a form's submit too, and stays pending until that read has landed, so nothing flickers. The writes chain in the System's queue, none waiting for the user's next click: each is decided on the System the client holds when its turn comes, and a refusal `decide` foresees goes to its channel with no call made. While one is on its way, leaving the page asks first (`useLeaveGuard`).
- **An edit sends what changed.** `useEditTileSubmit` compares the form with the Tile it opened on and sends only the fields that differ, so the Body of an untitled Root can be written before its name, with that Tile's Version, so a save over a Tile changed meanwhile, in another tab or by an agent, is refused rather than overwriting it.
- **A write names the Versions the screen drew.** Every write to an existing Tile carries the Version the page showed of it, the System with the writes still pending folded over it, so a write queued behind another of the same Tile names the Version that one leaves; the overlay folds it as any Operation, and Mapping's `decide` refuses it, foreseen or on the server, once the Tile changed under it, a refused write before it included.
- **The design system is a page of the app, for anyone, in production too**: `/design-system`, a deck of slides on the screen's own pieces (`ui/gallery/deck/`): why hexframe exists and its principles, in words; the chat, then the canvas, as the screen builds up, then the onboarding, a new account's first visit, on home's pieces, played again at will; the crossings, each on the whole screen; a chapter per side and one for what they share, each piece on the canvas and told in the chat, what it is for, what it is made of and where it is used; then every token. The route composes each slide, each folder's `gallery.tsx` in its chapter, the crossings (`ui/crossings.tsx`), which it hands Mapping's limit on a Preview, the timeline's words for a navigation and where a Turn works, the onboarding (`deck/tour.tsx`), the Message as home's composer sends it then Assistant's rule, the client's channels and a feature's own specimen where the piece is a feature's, and holds the slide, its piece and the canvas's view in its search params ([[4-software-engineering/1-projects/1-hexframe/1-app/src/front/ui/gallery/CLAUDE|gallery]], "The page").
