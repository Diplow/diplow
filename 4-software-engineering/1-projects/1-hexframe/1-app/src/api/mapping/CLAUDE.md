# mapping

Where the client meets [[4-software-engineering/1-projects/1-hexframe/1-app/src/domains/mapping/CLAUDE|Mapping]]. Each server function checks its input against a schema, then runs one of Mapping's Operations through `run`, for the Account the request proves, by its Session here, by its Key at `/mcp`, on the System the request names: that Account's own, unless a read names another, `system` by its star, the MCP's reads by a Tile of it.

## Rules

- **The Account is the one the request proves, never the caller's.** No input names an Account: `programs.ts` takes it from IAM's `signedIn`, whichever proof it was, and a signed-out call is `SignedOut`, which sends the user to sign in. `help` alone takes no Account, since Help is no Account's: it answers anyone.
- **Who acts and on which System are two things, resolved here.** Mapping takes `{ actor, system }`: the actor, the Account, its Groups and the owners it stands for, read from IAM on every request, never cached, for now the Account alone and in no Group, and whether a Session proves it, which every caller says: false for a Key, a Turn's Key and the Assistant's programs, an accepted Proposal's writes among them, published as its Turn's, so a move that would open a Tile to someone is refused them, and true for a server function a Session proves and for the user's own Undo; and the System, named by its star, the Account's own, both resolved in one function (`actingOnOwn`), which a read may trade for another: `system`'s input names its star, and the MCP's reads the Tile they start from, whose System's star Mapping finds (`holding`). A change always acts on the Account's own. A Turn's Key reads the System its Turn started in alone, its Account's own until HEX-134, whatever else the Account may read. Mapping decides what the actor may read and do there itself (`may`), so a System named wrongly shows its star's card at most, never another's Tiles, and a star that names none is `TileNotFound` (`hexframe-app-sharing-organizations/decisions.md#DEC-1` to `#DEC-3`).
- **Help and the tutorial come in the page's language.** `shipped` takes the System's Root and the language as its input, one of the app's locales (Paraglide's `locales`), which the page reads from its URL; a server function's own URL carries no locale. Its program passes both to Mapping, whose type requires each shipped System in each of them (`hexframe-app-mcp-server/decisions.md#DEC-19`, `hexframe-app-tutorial/decisions.md#DEC-1`).
- **The System is one read, flat.** `system` returns the whole of it (`hexframe-v0-mapping/decisions.md#DEC-6` in the run's registers) as the Account may see it, its Root and every Tile and Reference below it by id that it may read, each Tile with its rights on it and the gaps marked (Mapping's `Seen`), never its tree, the whole System for its owner; the client keeps it as one query, builds its tree with Mapping's `systemOf`, and reads it again after every write, and whenever the System's Version, which it polls through Assistant's `latest` beside the Conversation's last Entry ([[4-software-engineering/1-projects/1-hexframe/1-app/src/api/assistant/CLAUDE|assistant]]), moved past the Version it holds. `help` answers Help's tree, built on the server, as home draws it on the canvas, signed out or with Help open.
- **Tile ids are UUIDs.** A create's caller may choose its Tile's, which the client does to name the Tile before the answer comes; Mapping makes it otherwise, with `crypto.randomUUID()` (`Tiles.newId`), and the MCP's `create_tile` takes none. Mapping's `TileId`, which every Operation and every schema here takes, refuses any other string, so nothing else reaches the domain, and an id a Tile of any System already has is `TileIdTaken` ([[4-software-engineering/1-projects/1-hexframe/1-app/src/domains/mapping/CLAUDE|mapping]]). `create_tile`, which sends none, turns a `TileIdTaken` into a defect, so its description teaches no refusal an agent can't meet.
- **A change's input is its Operation's, never a schema of its own.** A field, a bound or a slot an Operation gains reaches its server function, its MCP write and the client's hook with no line written here; only the tag is left out, which the function's name says (`hexframe-app-optimistic-writes-and-patterns/decisions.md#DEC-8`).
- **An import comes as a form, at most 4 MB.** Start hands a server function a `FormData` as it came, so `ImportUpload` decodes it (`Schema.fromFormData`), and the client encodes its form by the same schema. Vercel caps a request's body at 4.5 MB, so the program refuses past 4 MB with `ImportRefused` (`UploadTooLarge`) before it reads a byte or asks who sent it; a larger import goes through storage first, later. The import is no MCP tool (`hexframe-app-import-export/decisions.md#DEC-11`).
- **The browser prunes an import; the server decides it.** `files/upload.ts` offers the client plain functions it calls in the page, as it calls observability's (`report/observability/client.ts`), and `front/client/mapping/import/upload.ts` composes them: Mapping's pure checks, `leftOutOf`, `skippedAsBinary` and `isSettingsFile` from `files/import/read.ts`, `pastBounds`, `pathFaults`, `stoppedAt`, `wrappingFolder` and `uploadFaults` from `landing/archive.ts`, never `landing/landing.ts`, which reaches the database, and the zip repository's `unpacked` and `archived`. It leaves out what the server would, so a vault fits the 4 MB more often, and refuses early what the server would refuse; the server reads and checks everything again (`hexframe-app-import-export/decisions.md#DEC-12`, `#DEC-16`).
- **The front follows Mapping's rules, never a copy.** A rule the front needs to offer only what Mapping takes is Mapping's: from its door when it is an entity's (`holdsNothing`, `isEmptySystem`), the front importing it directly; re-exported here when it lives in a concept folder, past the door (`files/download.ts`'s `isVerbatim`, `files/upload.ts`'s reading rules). A second rule in the front could drift from what Mapping refuses.
- **An export answers a raw `Response`.** Start hands a server function's `Response` to the client untouched, so `exportTile` streams its zip as it is zipped, past the 4.5 MB to which Vercel caps a buffered answer, as Vercel's guide says a streamed one goes, while its failure stays the `Outcome` every server function answers, carried to a write's channel (`hexframe-app-import-export/decisions.md#DEC-9`). Server-foundations' DEC-18 keeps raw server routes for inbound webhooks: the export needs none.
