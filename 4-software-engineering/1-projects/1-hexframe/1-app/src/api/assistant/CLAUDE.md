# assistant

## Rules

- **The Session alone.** Every program starts from IAM's `sessionOnly`: the Conversation is the user's, so a Key, which a server function never carries anyway, reads and writes none of it. `endTurn` and `turnEvent` alone do not: a Turn ends wherever it runs, the tab closed included, for the Account and the Turn the caller takes from the Turn's Key.
- **A Turn's Key goes to the sandbox alone.** `sendMessage` hands it, redacted, to `agent/`'s `startAgent`, which puts it in the launcher's environment, which the MCP client's config names for the agent to expand: never in a prompt, a file, a log, an answer or the database, which keeps only its hash.
- **A Turn's Key is revoked however it ended**: by its answer, its result or exit (`turnEvent`), a Stop (`stopTurn`), a limit (`modelCall`), its time (`sendMessage`'s next start), its sandbox (an agent that could not start), each in the transaction that ends it, through one helper, `revokingEnded`, run on the result of every step that may end one.
- **Every change lands, none waits on it.** The bus runs the subscription once the write's transaction committed, inside the request through its `waitUntil`; a rolled-back or refused write publishes nothing, so it lands nothing, and a subscription that fails is reported without touching the write it follows. A lost Entry is acceptable, as a lost event is ([[4-software-engineering/1-projects/1-hexframe/1-app/src/api/CLAUDE|api]], "The server bus").
- **Assistant decides, this layer routes.** For a write a Turn's Key made, Assistant answers draft or apply from the Turn's Mode, and only `proposal/written` reads the answer; a Proposal's writes are Mapping's Operations, which Assistant keeps opaque and this layer encodes and decodes by Mapping's `Batched`, and what undoes what was applied by Mapping's `Undo`.
- **A write in someone else's System is told twice**, a Turn's there included, as its agent's (HEX-134). In its owner's timeline, in the write's own transaction, the owner's Conversation locked before their System, as an accept and an undo take the two, so the Undo it offers is never lost; in the writer's, as their own, made elsewhere, once it committed, through the bus, so the writer's Conversation is never locked under another's System (`someone/`, HEX-132).
- **Mapping summarizes, Assistant records.** Assistant knows no Tile: the subscription asks Mapping for its summary of the event, the verb and each Tile with its Title, read once the change committed, a deleted Tile's from its event, and hands it on as it came. A Tile shared comes the same way, Mapping's `TileShared` carrying the Tile's Title as it was then, and lands in the Conversation of the Account it names, the one Entry recorded into a Conversation by another Account's request; it is told once its Grant committed, in a transaction of its own, so a Grant never waits on a Conversation's lock, and a lost Entry is acceptable, as a lost event is.
