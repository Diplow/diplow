# entities

What [[4-software-engineering/1-projects/1-hexframe/1-app/src/domains/mapping/CLAUDE|Mapping]] is made of, and the invariants each holds, apart from how a change loads, decides and writes (`mapping.ts`). Pure by what it is, so the front imports it: `index.ts` is part of Mapping's door, with `operations/index.ts` and `errors.ts`, and what the door may reach is [[4-software-engineering/1-projects/1-hexframe/1-app/src/domains/CLAUDE|domains]]' to say ("The door").

| File | Holds |
|---|---|
| `index.ts` | The door: everything below, re-exported, which Mapping's other folders, the API layer and the front import from |
| `tile.ts` | `Tile` and its `Content`; `TileId`, a Tile's id as a caller names it, a UUID, which every Operation and the API layer's reads take; `Version`, how many events touched a Tile, a whole number from 1 bounded as its column, which every write to an existing Tile names; `Direction` (1 to 6), `ContextDirection` (−1 to −6), a Leaf's slot (`{ leaf: 1 }` to `{ leaf: 6 }`) and `Slot`, any of them, each an Effect Schema and its type, which the API layer decodes its inputs by and the front a URL, `isLeafSlot` and `isContextSlot`, which kind of slot one is, and `contextSlotOf`, the Context slot in a Direction, which the front asks too; `rowDirection`, `leafOf` and `slotOfRow`, the slot a row's direction stands for, the one place that knows a row stores a Leaf slot as 7 to 12 (`hexframe-app-import-export/decisions.md#DEC-1`); `sameSlot`, whether two slots are one; `checked`, what a Tile's content must be, a `Result`, and `previewLimit`, the 350 characters it counts against, which `fitsPreview` counts as a reader does; `contentBounds`, the most a Title and a Body hold, which the API checks every input against and an import every file |
| `rows.ts` | The rows a System is read from, as Mapping reads them: `Row`, with its Tile's `version` and, on the Root's, the System's `systemVersion`, `RowWith`, a row with its Version and only the fields asked of its content, `FieldsAsked`, what a read asks of the Tile it opens and of those below, and `contentWith` and `withContent`, the one projection a read makes, which nests the flat rows the tiles repository selects, or a shipped System's notes give, into a `RowWith`. Mapping declares them, and the tiles repository's rows satisfy them structurally, so nothing here imports the repository (`hexframe-app-optimistic-writes-and-patterns/decisions.md#DEC-1`) |
| `star.ts` | A star as anyone finds it (HEX-130): `StarQuery`, what a star search takes, trimmed, 2 to 100 UTF-16 units, so a search never lists the stars a letter at a time, and `starQueryOf`, the query what is typed makes, its first 100 units past them, none while too short, which the front asks before it searches; `starsFoundAtMost`, 6, the most a search answers; `StarCard`, a star by its id and its card, its Title and Preview; and `LinkedStar`, where a link leads, to a star by its card, to the reader's own, or `nowhere`, one value for every way a link fails, which `sharing/stars.ts` and the API layer both answer |
| `system.ts` | `System`, Mapping's aggregate, flat: its Root apart, every Tile (`PlacedTile`) and Reference (`PlacedReference`) below it by id, each with its parent and its slot, whether an Account owns it, which no Account does of a System hexframe ships, Help or the tutorial, so a change can refuse one from the System alone, and `shippedRoots`, the ids of those Systems' Roots, `help` and `tutorial`, each its folder's name, by which the API reads them and the front asks for them, and its Version, how many events changed it; `systemFrom`, the System a repository's rows, or a shipped System's notes, hold, at the Version its Root's row keeps; its tree, a view: `SystemTile`, a Tile (`FoundTile`, with its Version and what it keeps from its files), and its Branches and its Leaves (`LeafTile`, a `FoundTile` with nothing below) by Direction and its Context by slot, built from the flat System by `systemOf`, which the client runs on what `system` answers and `shipped/` on Help and the tutorial; the pure reading of a flat System, which `decide` and `evolve` rule by: `tileAt`, a Tile by its id, its Root or one placed below it, never a Reference; `heldAt`, the Tile or the Reference in a slot; `below`, a Tile and everything below it; and of its rows, `tileRow`, a Tile's row by its id, which `landing/` reads; `Found`, what a read from one Tile finds before it is shaped, the Tile's row with the fields asked of it apart from the rows below with theirs, and `showing`, a row with fewer of its fields; `foundIn`, what a read from one Tile finds in a System held whole, as the repository finds it in the database, which a read through a batch takes; and `ReadTile`, a Tile as `readTile` finds it, built by `readOf`, with the `fields` a read may ask and the `depths` it may go to: its id, its Version and the `Field`s asked, its Branches, Leaves (`ReadLeaf`) and Context above the read's last generation, a Reference as its Tile's id, Title and Preview |
| `system.test.ts` | That reading on rows and Systems made by hand, no database: the flat System, each Tile and Reference where it stands, owned or, Help's, not, and what it leaves out; its tree: the Root, a Child and a Context Tile in place, Help's drawn as an Account's, a Leaf beside the Branch sharing its Direction, a Reference resolved and a broken one; a Tile by its id, what holds a slot, what lies below a Tile; and a Tile read to a depth: where it stops, the fields it carries, its References |

| Folder | Holds |
|---|---|
| `leaves/` | What a Leaf may hold, nothing: `leaves.ts`, the two checks `decide` runs on a flat System, each a `Result`, `notLeaf`, nothing created nor moved under a Leaf, and `holdsNothingIfLeaf`, nothing that holds anything into a Leaf slot, which `freeSlot` and a move and a swap call, and `onlyALeafIn`, an import into a Leaf slot only one file alone, which `landing/` calls; and what holds nothing, on a System as a read finds it, `holdsNothing`, a Tile with nothing below it, the one Branch that shrinks into a Leaf, and `isEmptySystem`, an untitled Root without Preview nor Body holding nothing, the one System an import lands as the Root of, which `landing/` calls and the front follows to offer only what Mapping takes; `leaves.test.ts`, those checks on a System made by hand, where a Leaf slot is stored and which kind a slot is, on slots made by hand, and what holds nothing on Systems made by hand, the flat System's rule agreeing with its tree's. Leaves over PGlite are `../leaves.test.ts`'s (`hexframe-app-import-export/decisions.md#DEC-3`) |
| `rights/` | The rights on a Tile and the Grants they come from: `rights.ts`, `Right` (`read`, `write`, `@`), `Reading` (*read* to *read+write+@*), `GrantValue` (*none* and those), a `Subject`, an Account, a Group or Everyone, and `Grant`, a Tile's value for one, a Schema that refuses Everyone more than *read*; `GrantRow`, a Grant as the tiles repository keeps it, which its rows satisfy, and `grantOf`, the Grant a row keeps, none for a row that is no Grant; `Actor`, who acts as the API layer hands them over, their Account, Groups, the owners they stand for and whether a Session proves the request, and `owns`, whether they stand for an owner; `Lineage`, where each Tile stands, from rows (`lineageFrom`) or a flat System (`lineageOf`); `Sharing`, a System as its rights are read, built by `sharingOf`; `Everyone`, its Schema; `subjectKeyOf`, a subject's key, the same for two equal subjects, which the share widget keys its rows by; `subjectRowOf`, a subject as a row names it, the inverse of `grantOf`'s reading; and the resolution, `originOn`, a subject's nearest explicit value walking up and the Tile it is set on, *none* from nowhere at the star and on a walk that loops, `valueOn`, that value alone, `rightsOf`, the rights a value gives, which the front words, `heldBy`, the rights a subject holds on a Tile, and `rightsOn`, an actor's rights, every one for its owner, else the union over the subjects covering them. `rights.test.ts`, the grill's scenario and the rest on Systems made by hand. `reach.ts`, who reaches a Tile as its owner reads it in the Share widget: `Reach`, a subject, its value there and the Tile it comes from, none where nothing above sets one; `reachOn`, `Reaching`, Everyone always, then each other subject a Grant names that reaches it or has a Grant on the Tile itself; `accountsIn`, the Accounts among them, and `namedBy`, each named by its star's card (`NamedReach`, none for a Group or an Account with no star); `EveryoneChoice`, what the owner sets for Everyone, `read`, `none` or `inherit`, and `Choice`, for someone, any value or `inherit`, whose literals the Share widget offers; `choiceOn`, a value read as the owner's choice on the Tile, `GrantChange`'s inverse, its value where set there, else `inherit`; `GrantChange`, what the owner sets, Everyone's `read`, `none` or `inherit`, which removes its Grant, or someone's by their star, a UUID, never an Account's id, any `Choice` (HEX-131), a Tile by its UUID; and `opens`, whether a choice first opens the Tile to its subject by a Grant of its own, nothing set there before, read or more after (`Reading`, `rights.ts`'s), what tells someone once per Grant in their timeline; `reach.test.ts`, that on a System made by hand (`hexframe-app-sharing-organizations/decisions.md#DEC-5`, `#DEC-8`). `seen.ts`, a System as an actor may see it: `Seen`, the flat System with only what they may read, their rights on each Tile by id and the gaps, the Tiles they may read below one they may not, hung from the star with no place, since theirs would tell of the Tile kept from them; `carded`, the one rule of a card, its Title and Preview, its Body empty, its Version the first, on a Tile or a row, `cardOf`, a star as anyone sees it; `sightOf`, what an actor may read of a System and what they are shown, that and the star, and `shownRow`, whether a row they come upon is shown them, a Reference only with the Tile it points at, the one reading of it that `seenBy` and the service's reads from one Tile share; and `seenBy`, the System seen, whole for its owner, every right and no gap, for anyone else a Reference to a Tile they may not read left out and, for the System's Version, how what they see stands (`sightVersion`, a hash of the star as they see it, each Tile and Reference they see where it stands, each Tile's Version and their rights, no count of the System's changes, which would tell of the Tiles kept from them; HEX-132). `seen.test.ts`, that on a System made by hand, `sightVersion` staying for a change kept from the reader and moving for one they see. `may`, asked of an Operation, is `../operations/rights/`'s (`hexframe-app-sharing-organizations/decisions.md#DEC-2`, `#DEC-3`) |
| `kept/` | What a Tile keeps from its files: `kept.ts`, `isSegment`, the one check of a path segment, which an export runs again on every name it writes, `isFolderPattern`, and the Schemas a write's types come from, `Name`, `TileConfig` and `Frontmatter`, so only a checked value is stored; `named` and `configured`, a Name and a Tile config or `NameInvalid` on the field at fault, and `keepable`, the same checks as guards, for an import that lists every fault; `Kept`, what a Tile keeps as a read finds it, typed from the row's parts, and `keptOf`, what a row keeps, as a Tile shows it; `naming.ts`, `inherited`, a config's parts over the naming above it, by which an export and an import work out the naming in force at each folder, and `defaultNaming`; `kept.test.ts`, those checks on values and rows made by hand. What a Tile keeps over PGlite is `../kept.test.ts`'s (`hexframe-app-import-export/decisions.md#DEC-4`, `#DEC-5`) |
