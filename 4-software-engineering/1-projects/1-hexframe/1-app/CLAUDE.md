# app

`@hexframe/app`, the TanStack Start app that holds hexframe's client and server. The choices behind it are in [[4-software-engineering/1-projects/1-hexframe/STACK|STACK]]; this file says where things sit in the package.

## Scripts

Run them here or, for every package at once, from the monorepo root.

| Script | Does |
|---|---|
| `dev` | Vite's dev server, on the first free port from 5173 (`pnpm dev --port <n>` to pick one). Without `DATABASE_URL`, accounts live in an in-memory PGlite, gone on restart |
| `build` | Nitro's server build for Vercel, in `.output/` (`.vercel/output/` on Vercel), then a check that the client bundle holds no server code |
| `check` | Compiles the Paraglide messages, type-checks, then runs the lint set below |
| `test` | Vitest, once, with `@effect/vitest` for Effect programs |
| `db:generate` | drizzle-kit writes the next migration from the schema into `migrations/` (`--name <what-changed>`) |
| `db:migrate` | Applies the committed migrations to the database `DATABASE_URL` names |

## Layout

| Path | Holds |
|---|---|
| `src/front/` | What the browser shows: the routes, the features they compose, the design system, the client's side of the API, and the theme's `styles.css`: [[4-software-engineering/1-projects/1-hexframe/1-app/src/front/CLAUDE\|front]] |
| `src/api/` | Server functions, a folder per domain, the helper that runs their Effect programs, and the error model the client decodes: [[4-software-engineering/1-projects/1-hexframe/1-app/src/api/CLAUDE\|api]] |
| `src/domains/` | One folder per domain; `kind.ts`, the kinds their errors carry; and `bus.ts`, where they publish their events: [[4-software-engineering/1-projects/1-hexframe/1-app/src/domains/CLAUDE\|domains]] |
| `src/repositories/` | Effect layers over the SDKs, the database, auth and observability: [[4-software-engineering/1-projects/1-hexframe/1-app/src/repositories/CLAUDE\|repositories]] |
| `migrations/`, `drizzle.config.ts` | The database's migrations, generated by drizzle-kit and committed, and drizzle-kit's settings |
| `vercel.json` | Vercel's build command: the migrations, over `DATABASE_URL_UNPOOLED`, then `build` |
| `src/router.tsx`, `src/server.ts`, `src/start.ts` | The router, which strips and adds the locale prefix, holds the QueryClient and starts Sentry and PostHog in the browser; the server entry, which starts Sentry, traces each request and runs Paraglide's middleware; and Start's settings, which run the API layer's middleware before every server function: a cross-site call refused, then the request's context |
| `src/routeTree.gen.ts` | Generated by the router plugin on `dev` and `build`, from `src/front/routes/` (`vite.config.ts`); committed, so `check` runs without a build |
| `paraglide/` | Generated message functions, imported as `#/paraglide/*` (`tsconfig.json`, `package.json`); ignored by git, and outside `src/` so the rule of 6 leaves it out (`src/routeTree.gen.ts`, generated too, counts as one of `src/`'s files) |
| `messages/`, `project.inlang/` | One JSON file of messages per language, and the Paraglide project that reads them |
| `scripts/` | What no tool covers: the rule of 6, which `check` runs; the client bundle check, which `build` runs; `lint.test.ts`, which `test` runs to prove the custom lint rules fire; and `migrate.ts`, behind `db:migrate`, with the test that proves it loads under plain Node |

## Shape: the rule of 6 inside the code

Every folder under `1-app/src/` is a node: at most 6 child folders and 6 files, not counting its `CLAUDE.md` (nor a stray `.DS_Store`); `scripts/check-rule-of-six.ts` enforces it in `check`. Names are plain inside the code (`domains/iam/`, not `domains/1-iam/`): numbers stay on packages and vault nodes, where the ring means something.

## Lint

`pnpm check` runs all of it and CI enforces it; no pre-commit hook. `pnpm exec eslint --fix .` and `pnpm exec prettier --write .` fix what they can.

| Rule | Tool |
|---|---|
| Strict types | ESLint flat config (`eslint.config.ts`), `typescript-eslint` strict type-checked |
| At most 6 folders and 6 files per folder | `scripts/check-rule-of-six.ts`: no ESLint plugin counts a folder's children |
| Layer direction, no domain importing another, no feature importing another, a third-party SDK imported only by its repository | `dependency-cruiser` (`dependency-cruiser.config.ts`) |
| Dead code: files, exports, dependencies | `knip` |
| Cognitive complexity at most 15 | `eslint-plugin-sonarjs` |
| At most 150 lines per function, 5 parameters (an object beyond), 600 lines per file, blank lines and comments aside | ESLint core |
| No `zod`, however it is imported: validation is Effect Schema | `dependency-cruiser` |
| Radix, TanStack Table, TanStack Form, the Markdown renderer, TanStack Hotkeys and Sonner imported by `src/front/ui/` only | `dependency-cruiser` |
| No hex and no Tailwind palette name (`bg-zinc-900`, `text-white`) in a string under `src/`: colour is a theme token | ESLint `no-restricted-syntax` |
| No raw `<table>` or `<dialog>` outside `src/front/ui/` | ESLint `no-restricted-syntax` |
| No `useEffect` (nor `useLayoutEffect`, `useInsertionEffect`) outside `src/front/ui/`: state has an owner | ESLint `no-restricted-syntax` |
| No Effect `run*` (`runPromise`, `runSync`, `runFork`, `runCallback`…) outside `src/api/server/run.ts`: the helper runs every program | ESLint `no-restricted-syntax` |
| No `.ts` or `.tsx` in an import path in a linted file under `src/`, but in `src/repositories/database/migrations.ts`, which `scripts/migrate.ts` runs under plain Node | ESLint `no-restricted-imports` |
| Formatting: no semicolons, single quotes, 100 columns | Prettier (`.prettierrc.json`) |

**The layers have their folders before their code.** dependency-cruiser reads them as `src/front/` → `src/api/` → `src/domains/<domain>/` → `src/repositories/<repository>/`, and inside the front as `routes/` → `features/<feature>/` → `client/` and `ui/`; an import only points down, so nothing below the front can reach what the browser shows, the front never skips `api/`, and neither a domain nor a feature imports another of its kind. Which repository alone imports which SDK is documented in [[4-software-engineering/1-projects/1-hexframe/1-app/src/repositories/CLAUDE|repositories]]. Import & export will let three places reach outside the package, into the shape in `2-claude-mod/hooks/shape/`: `src/domains/mapping/` for its reading rules, `src/front/ui/hex/` for its layout, and `src/front/client/mapping/` for `exclusions.ts` alone, to leave excluded names out of an upload, each named in dependency-cruiser and nothing else ([[4-software-engineering/1-projects/1-hexframe/1-app/src/domains/mapping/CLAUDE|mapping]] and [[4-software-engineering/1-projects/1-hexframe/1-app/src/front/ui/hex/CLAUDE|hex]], "Later").

**The escape hatch is a comment.** When splitting would not make the code clearer to its next reader, human or agent, a rule can be disabled on the spot with a `-- reason` that says why; a disable without one fails the lint (`eslint-comments/require-description`), and so does one that no longer disables anything. cubic reads the reasons.

## Rules

- **The locale lives in the URL.** `/` is English, `/fr/…` French, so a link shows what its sender saw. Switching languages is a plain link and a full page load.
- **The theme is a class on `<html>`**, set before the first paint by an inline script, from the stored choice or the system's preference. `useThemeState` reads and writes it.
- **Nitro is a beta**, allowed because it sits behind a seam: its one line in `vite.config.ts`. Vercel's docs deploy TanStack Start through it.
- **Vercel's project is `hexframe-app`**, rooted here, on Node 24 (Vercel's newest; local and CI run Node 26). It skips a build when nothing under `1-hexframe/` changed, and migrates the deployment's database before it builds (`vercel.json`). Neon's Vercel integration gives each deployment its database, `DATABASE_URL` and `DATABASE_URL_UNPOOLED`: its git branch's Neon branch on a preview, `main` in production. Every deployed environment also needs `BETTER_AUTH_SECRET`: without it, every server function answers `Unexpected`. Sentry needs `VITE_SENTRY_DSN`, PostHog `VITE_POSTHOG_KEY` and `VITE_POSTHOG_HOST`, all public and read at build time; each stays off without its own ([[4-software-engineering/1-projects/1-hexframe/1-app/src/repositories/observability/CLAUDE|observability]]).
- **shadcn adds components to `src/front/ui/`**; move each into the folder it belongs to. `cn` comes from shadcn's `cn` package, not a local helper.
