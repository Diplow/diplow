# Decisions

### DEC-1 Three folders regroup before the Assistant lands: `api/report/`, `routes/(access)/`, and conversation's `timeline/` and `entry/`

HEX-74, [#84](https://github.com/Diplow/diplow/pull/84). Three folders the Assistant adds to were full (MR-8): `api/` held six folders, `front/routes/` six files, `front/features/conversation/` six files. Each regroup is a move, no behavior changes.

- **`api/report/`** holds `errors/` and `observability/`, each its own subfolder, observability keeping its `CLAUDE.md`. They are the two folders of `api/` that belong to no domain and no door: what the layer tells of a call, to the user (a failure's wire form, its channel, its message) and to us (what is logged, what reaches Sentry and PostHog). `report` names that. `dev/` stays at the root, as DEC-11 of `hexframe-app-mcp-server/decisions.md` left it: it holds server functions, where `report/` holds none. `api/` now holds five folders, a place left for `assistant/`. Imports through `#/api/report/…`; dependency-cruiser and knip name neither folder.
- **`front/routes/(access)/`** holds `sign-in.tsx` and `sign-up.tsx`, a pathless group: TanStack Router leaves a `(name)` folder out of the path, so the URLs stay `/sign-in` and `/sign-up`, and `/fr/sign-in` and `/fr/sign-up` through the router's locale rewrite. The route ids become `/(access)/sign-in` and `/(access)/sign-up`; every link goes `to` the path, which did not change. `routes/` now holds four files and three folders, a place left for `assistant/`.
- **`front/features/conversation/`** splits by what each file holds: `timeline/`, the timeline's model and its test, pure; `entry/`, the Entry's views, `Entry.tsx` and `TileCard.tsx`. `Conversation.tsx`, the feature's face, and `fixtures.ts`, what `/dev/system` lays out, stay at the root, which now holds two files and two folders, room for the composer, the Proposal and the Turn views.

### DEC-2 A pending System write is read once per state of its mutation

HEX-74, [#84](https://github.com/Diplow/diplow/pull/84). The unit gate's `test` already failed on `project/assistant` before any move, one run in two, and in every run of the gates on this branch: two of `useRefusalState.test.ts`'s cases took about 2 s each alone and passed their 5 s timeout under a full run's load. A CPU profile showed renders feeding each other. `useSystem`'s `useMutationState` selected `pendingOf`, which decoded each pending write's Operation again at every MutationCache notification. A decoded Operation is a new object `replaceEqualDeep` cannot compare, so every notification rendered the page again, and each render's `useMutation` effects called `setOptions`, which notified again. `pendingOf` now keeps what it read in a `WeakMap` keyed by the mutation's state, which TanStack Query replaces at each change, so a write is read again only when it changed. The cases now take about 160 ms. No behavior changes: the same values, read once. Raising the test's timeout was the other way, refused because it hides the render loop instead of ending it.

### DEC-3 A Tile's Version counts the events naming it as the Tile they change; the client sends the Version it drew

HEX-75. The ticket asked for a count of the events that touched a Tile, checked on every write to an existing one, the Reference writes on the Tile whose slot they change. What counts follows from what is checked: an event counts on the Tiles whose Version a write to it names. `TileEdited`, `TileMoved` and `TilesSwapped` count on the Tiles they change; `ReferenceCreated` and `ReferenceDeleted` on the Tile holding the slot, since a Reference has no Version of its own; `TileCreated` makes one at 1 and counts on no parent, nor does a move on the parents it leaves and joins, since a create names no Version and a slot taken meanwhile is `DirectionTaken`'s. An import landing as the Root, no Operation, counts one on the Root it fills, since it replaces what the Root says; an import into a free slot counts on no parent, as a create. The tiles repository's `update` requires a Version, so no change to a row leaves it behind. `decide` checks the Version right after finding the Tile, before every other rule but the Root's (`RootFixed`), so a stale write is refused whatever else it would meet, its no-ops included. The service writes each Tile at the Version `evolve` gave it in the System after the event, so the database and the overlay never disagree on one; `agreement.test.ts` compares them, Versions included.

The screens send the Version they drew, the System with the pending writes folded over it, as the ticket said. Two things follow. A read that already holds a pending write has moved its Tiles' Versions on, so `decide` refuses folding it again: the swap's own check, which compared where its Tiles stood with where they stand (`holdsSwap` and the System recorded when a write was made), is retired, since the Version now does it for every write. And a write queued behind a refused write to the same Tile names a Version the server never gave it, so it is refused too, `TileChanged`, foreseen and sent nowhere, an edit's form reopened with what the user typed. The other way, sending the Version the server last answered, refuses every second write a user queues on one Tile before the first lands, the common case, where this one refuses only behind a refusal. An edit's form keeps the Version of the Tile it opened on for as long as it is open (`useEditTileSubmit`): the page redraws the Tile when a read lands, and a form sending the Version it is drawn at now would let a save from another tab through unseen, as the first look at it in a browser showed.

### DEC-4 The agreement test moves beside the Decider, and Mapping's PGlite tests share `testing.ts`

HEX-75. Every write in Mapping's PGlite tests now names a Version, and `mapping.test.ts` stood at the 600 lines its lint allows; `domains/mapping/` held six files. `agreement.test.ts` moves to `operations/decider/`, beside `decide` and `evolve` whose agreement with the service it pins: no rule keeps a test there from reaching the service, and nothing reachable through Mapping's door reaches it. The place it frees holds `testing.ts`, what `mapping.test.ts` and `leaves.test.ts` share: the tiles over PGlite with a bus that hears nothing, the System as its tree, and each change as the API layer runs it, naming each Tile at the Version it has just before. `leaves.test.ts` drops its copy of the same helpers. No test changes what it checks.

### DEC-5 The import's client files move into `front/client/mapping/import/`

HEX-76. The poll of the System's Version needed a file and its test in `front/client/mapping/`, which held six files (`files.ts`, `upload.ts`, `queries.ts` and their tests) and `overlay/`; `queries.test.ts` stood at the 600 lines its lint allows, so the poll's tests could not join it. `files.ts` and `upload.ts`, with their tests, are the browser's side of an import, what the user hands it and how it is pruned and zipped, so they move together into `import/`. `mapping/` now holds `queries.ts`, `follow.ts` and their tests, `overlay/` and `import/`. A move, no behavior changes: `queries.ts` and `features/system/import/state/useImportState.ts` import through the new path, and the docs naming the old one follow.

### DEC-6 The System's Version lives on the Root's row; an import's event counts the Tiles below the one it landed

HEX-76. The ticket asked for a System Version `evolve` bumps on every event, a read of it the page polls, and an import publishing `TilesImported`, the Tile it landed and how many came with it. Three choices followed.

- **Where it is kept.** A `system_version` column on `tile`, read on the Root's row, 0 on every other, unread, as a Reference's `version` stays 1. The Root's row is the one every change already locks (`Tiles.lock`), so a change reads and writes the Version under that lock and two never share one, and the poll's read is one row by the unique index on the Root, `tile_root_idx`. A `system` table beside `tile` was the other way: one more table, and a second row to lock or to keep in step with the Root's, for one integer. The column starts at 0, so a System changed before the migration counts from 0 too: a poll compares two of its reads, never a Version with a count of the past. `System.version` is a plain number from 0, not a Tile's `Version`, which starts at 1.
- **What counts.** `evolve` counts every event one, an Operation's and an import's alike, an event naming what the System doesn't hold included: an event is a fact the service wrote, so the database counts it too, and `agreement.test.ts` keeps the two in step. A change that made none, refused or a no-op, writes no Version (`ended`, in `mapping.ts`, which writes the Version and then publishes). `Row` carries `systemVersion` on every row, 0 but on the Root's, rather than a shape of its own for the Root, so the rows a change locks and the rows a read selects stay one type, and the System is built from them in one pass. `MappingEvent` splits into `OperationEvent`, what `decide` answers and the service writes one change each, and `TilesImported`, so neither `decide` nor `written` must handle an event no Operation makes.
- **What `TilesImported` says.** `id`, the Tile the import landed as, a new one or the Root it filled, and `count`, the Tiles that came with it below it, Branches, Leaves and Context Tiles, its References aside, since a Reference is no Tile: a timeline entry reads "imported X and n Tiles". The plan makes it (`importedAs`, `files/import/plan.ts`), pure, once the batch gave the new Tile its id. It names none of the Tiles it brought, so `evolve` counts it on the System and, as DEC-3 has it, on the Root it filled, and a reader reads the System again; the Root's Version an import as the Root writes is the one `evolve` gives, no longer counted by hand.

The page polls the Version on focus, and every 2 s while `useFollowSystem` is told to follow closely, and reads the System again only when the Version moved past the one its cache holds. The System's read is no longer refetched on focus, so a focus costs one small read rather than every Body. Seen in a browser on the dev server: a Tile created through the MCP with a Key showed on an open canvas once the tab became visible again, its focus simulated by a `visibilitychange`, since the driven browser's window stays hidden.

### DEC-7 The canvas names ten gestures, the timeline speaks them, and picking the ring shown changes nothing

HEX-77. The ticket asked the canvas to say which gesture changed the view, on which Tile, and the timeline to take the canvas's words where they differed. Three choices followed.

- **Whose words.** The canvas's, imperative, as `TileAction` already had them: `center`, `expand`, `collapse`, `show-context`, `hide-context`, `hide-leaves`. The timeline's `centered`, `expanded`, `collapsed`, `context-shown` and `context-hidden` go; its entry's field is now `gesture`, typed from `Navigated['gesture']`, and its messages keep their past tense. `Gesture` and `ViewAction`, a gesture and its Tile, are Effect Schemas in `ui/hex/view/view.ts`, beside `TileId`, and `Navigated` in `features/facts.ts` is built from `ViewAction`'s fields, so the pair is declared once, decoded at a crossing, and the canvas never knows the bus.
- **The ring row is a gesture too.** A click names five, but the row above the canvas changes the view as well, so it names its own: `show-leaves`, the one inside the center no click shows, and `show-children-around`, `show-branches-around`, `show-leaves-around` for the ring around it, the `-around` keeping the Leaves around the center apart from the Leaves inside it. Children is never offered beside another kind today (`kindsOf`), but `showAround` takes any `OuterKind`, so the name is there for it. A ring's gesture is made on the center. The breadcrumb's click is a `center` on the ancestor.
- **Picking the ring shown changes nothing.** The row used to navigate to the same view, tidied, when its pressed button was pressed again. Nothing changed there, so no gesture happened and no fact is published: the hook calls `onViewChange` only when the ring picked differs from the one shown.

`Navigated` carries the gesture and the Tile's id, no time and no Title: the conversation ticket (HEX-78) merges consecutive ones and joins the Tile in.

### DEC-8 The Conversation keeps its Entries as JSON, a deleted Tile's Title rides on its event, and the navigation under way waits in the page

HEX-78, [#88](https://github.com/Diplow/diplow/pull/88). The ticket asked for the Assistant domain, a Conversation per Account recording Messages, every change to the System with who acted, imports and merged navigations, the bus subscription that records the changes, three server functions and the browser's navigation sender. Seven choices followed.

- **A deleted Tile's Title rides on its event.** The subscription runs once the write committed, so a Tile the change deleted is gone when Mapping's summary reads it. `TileDeleted` now says the Title its Tile had, which `decide` has in hand; reading it before the commit would make the bus wait on a read, and naming it from the timeline's own past would rebuild the record. Every other Title the event does not say is read once the change committed (`Mapping.summary`, through `Mapping.titles`), so a Tile changed again meanwhile is named as it then reads.
- **Two tables, an Entry's content one JSON column.** `conversation`, one row per Account, added with its first Entry, is where the Mode and the open Proposal will go; `conversation_entry` holds each Entry's id, instant and `content`, the Entry as Assistant's `EntryContent` encodes it. Four kinds share no field beyond their tag, so a column per field would leave most of every row empty, and the repository would have to know them; with one column it keeps what it is given, and Assistant decodes it by the schema that wrote it, a row it cannot read back being a defect. A `seq` identity orders two Entries of one instant as they were written. `account_id` has no key to `user`, as `tile`'s has none.
- **Who acted is read when the change is recorded.** "You" for a Session; for a Key, its name, read by IAM's `keyName` through Better Auth's own adapter, since `auth/` may not import `drizzle-orm`, and absent once the Key is revoked. Putting the name on the envelope's proof was the other way: it changes what the bus carries for every subscriber, and a Key renamed would still be named as it was, which no screen allows yet.
- **A gesture is a word Assistant keeps as it came.** A domain cannot import the canvas's `Gesture`, and DEC-7 keeps the words the canvas's own, so Assistant bounds a gesture as a lowercase word of dashes, 32 characters at most, and a Tile as the canvas names it, 100 at most, never a list of its own that could drift from the canvas's. A navigation keeps a Tile's id alone, and reading a day joins in the Titles the System holds then; a Tile deleted since is named by none.
- **The merge rule keeps the latest twelve gestures and counts every one**, so a long wander still reads as where the user ended up, and how much they moved.
- **A day is a date and an offset; a navigation says how long ago.** The server knows no time zone: a reader asks for a date of their calendar, today by default, and how many minutes their clock stands ahead of UTC at its midnight and at the next, and a day spans from the one to the other, 23 or 25 hours the day the clock changes, so every instant falls on one day. A merged navigation reaches the server once something else happens, and dates from its last gesture, which only the browser's clock saw: it sends how long ago that was, a day at most, never an instant, so two clocks never disagree on the order of the timeline.
- **The sender is a state hook whose navigation waits in a ref**, in `features/conversation/state/`, mounted on home. The navigation under way is an outbox nothing renders, so it waits in a ref rather than in a reducer, whose state would render the page at every gesture for nothing on screen. It is sent when a Message is posted, through the hook's `postMessage`, when a write to the System is made, heard on the MutationCache (`useEachSystemWrite`), when the page is hidden, and when home is left, the hook unmounting. A tab closed may still lose it: the request starts as the page hides, and a server function's call cannot ask the browser to keep it alive past the page, a loss accepted as a lost event on the bus is. The navigation and the Message share the Conversation's queue, so they reach the server in order. TanStack Query holds a queued write while the page is hidden, its retryer waiting for focus: a navigation sent on hiding while another write of the Conversation is still on its way goes once the page shows again.

The three server functions take the Session alone (`sessionOnly`): the Conversation is the user's, and a Key reads and writes none of it. Nothing decides yet, so Assistant has no Operations, no Decider and no errors; they come with the Turn. Its service still shapes each Entry itself, through an operation per kind (`postMessage`, `recordNavigation`, `recordChange`), so the API layer never decides what an event becomes in the timeline.

### DEC-9 The chat reads a day at a time and skips the empty ones, the poll compares the Entry last written, and home lays out canvas, breadcrumb and card in one column

HEX-79. The ticket asked for the chat on home over the Account's Conversation, earlier days reachable by scrolling back, the page's poll extended to the Conversation's last Entry, and the layout of Q29: the chat in the side column, the Breadcrumb above the canvas, the Tile forms as their drawer. Five choices followed.

- **Scrolling back skips the empty days.** A reader who last wrote a week ago would otherwise click through six empty days. Each day the server answers carries `earlier`, the instant of the latest Entry before it (Assistant's `before`), and the browser turns that instant into its own calendar's date, so the server still knows no time zone. The days are one infinite query, `['conversationDay', 'read']`, today first, so every write's read-again and the poll's reach all of them at once. A button above the oldest day shown reads the next one: loading as the reader scrolls would need an `IntersectionObserver` in an effect, which only `ui/` may hold, for a gesture a button already gives.
- **The poll compares the Entry last written, not the latest instant.** `latest` answers `lastEntry`, the id of the Entry with the highest `seq`, and each day's answer carries the same `lastEntry`, read before the day's Entries, so an Entry recorded between the two reads is among the day's and costs at most one read again, never a miss. Ordering by `at` would miss a navigation another tab sent late, dated back before the last Message. An index on `(conversation_id, seq)`, `conversation_entry_seq_idx`, makes it one row read from the end of the index, since the page asks every 2 s while a Turn runs.
- **One server function, Assistant's, composes the poll.** `latest` lives in `api/assistant/` and answers Mapping's `systemVersion` and Assistant's `lastEntry` in one request, as the project's grill decided ("one small read"). Mapping's own `systemVersion` server function had no other caller, so it is gone, and its test of the Version moving once per change, never for a refusal, moved to `latest`'s. `useFollowSystem` becomes `useFollowLatest` and moves to `front/client/assistant/follow.ts`, since it now follows both.
- **A write the page made reads the Conversation through the poll.** The server records a change in the Conversation once its transaction committed, in the bus's subscription, so the write's own answer cannot carry it. The page polls `latest` once each of its System writes has settled, which is after the System's read-again landed, a round trip after the commit: seen in a browser, an edit showed in the chat with no focus change. A Turn's 2 s poll will cover the rare subscription slower than that.
- **The layout keeps one column for the System.** The canvas's column holds the Breadcrumb above the canvas, now one line that wraps, and the centered Tile's card below it, at most 30% of the height and scrolled past that; the chat takes the side column, 24rem wide. The Tile forms were already a drawer and stay one. `/dev/system` takes the same layout on its fixtures, which become Assistant's Entries, so one `Conversation` renders both. Who acted starts each change's sentence, "You edited Games" or "The key “CI” created Games", one message for the user and one for anyone else per verb, since French conjugates the two apart ("Vous avez créé", "La clé « CI » a créé"); an import counts with three messages, none, one and many, Paraglide's messages here carrying no plural. The Tile card a change used to show went with the Preview the fixtures had and Assistant's Entries do not carry; `excerpt` now shortens a long Message, past 800 characters, until the reader asks for the rest.

Seen in a browser on the dev server, light and dark, English and French: a Root renamed, a Tile created and a Message sent each showed in the chat and stayed after a reload; two Tiles created through the MCP with a Key showed on the canvas and in the chat as "The key “local test” created …" once the tab's focus was simulated, since the driven browser's window stays hidden (DEC-6).

### DEC-10 One `repositories/agent/` for the sandbox and the relay; a sandbox named by a hash, read-only by its modes, interrupted from inside, its egress set through the SDK but not yet seen

HEX-80. The ticket asked for the sandbox repository, the only importer of `@blaxel/core`, an Effect service and a fake on this machine, Mapping answering where a Tile lives in its export, and the API layer writing the System into the Account's sandbox. Six choices followed, and one thing was not seen.

- **Where it sits.** `repositories/` held five folders; `agent/` is the sixth, holding `sandbox/` now and `anthropic/` with the relay (HEX-82), so no regroup was needed. dependency-cruiser's `sdks` are keyed by a repository's path, `agent/sandbox` among them, its rule named `no-agent-sandbox-sdk-outside-its-repository`, which `scripts/lint.test.ts` proves fires.
- **A Box per Account.** `ensure(accountId)` answers a `Box` whose paths are all from its home, and a Turn uses it for its files and processes, rather than naming the Account in every call. The service has no typed error: Blaxel failing is a defect, as the database failing is.
- **The name is a hash.** `hexframe-` and 32 hex digits of the SHA-256 of a namespace and the Account's id: Blaxel never sees the id, and a preview's database, a branch of production's, holding the same Account never shares its sandbox, since the namespace is production's domain, else the branch's URL, else the deployment's, `local` off Vercel.
- **Read-only against a user of its own.** The System folder is wiped, written in one `writeTree`, given to root and set `a-w`, and `write` refuses a path inside it. Modes hold against any user but root, and Blaxel's `exec` takes no user, so each sandbox gets a user, `hexframe`, made by `useradd` when missing, and every process starts through `setpriv` as that user, which execs, so the pid a stop signals stays the process's own. The home is root's, so the agent can't rename the System folder away; its HOME is `work/`, its own. The fake runs as this process's user, whom the modes hold. The Turn (HEX-83) keeps Claude Code's writing tools off too.
- **A stop interrupts from inside.** Blaxel's API offers a stop and a kill, neither naming SIGINT, so the layer sends `kill -INT` to the process's pid from a command it runs in the sandbox, as root, waits 10 s, then kills. The signal reaches the process the command line became, so the Turn's script ends in `exec`; the fake signals the process alone too, so a script that forgets is caught in tests, and kills the whole group. Both read a process's state by how it ended (`ended`), never by who ended it.
- **Egress through Blaxel's proxy, set from the SDK.** The SDK's create takes Blaxel's network rules (`network.proxy.allowedDomains`, and the firewall's `proxy` ruleset so no process goes around the proxy), so a sandbox is made reaching the deployment's hosts alone, `localhost` off Vercel, and one made before its hosts changed has its network set again when ensured. Without credentials (`BL_WORKSPACE`, `BL_API_KEY`) the layer still builds and ensuring a sandbox is a defect, so a deployment without them runs as before.
- **Not seen working against Blaxel.** No Blaxel workspace is configured where this ran, so the pass by hand (ensure, write, `ls -R`, an outbound request elsewhere than the app, stop) did not run. The egress rule, the home `/blaxel/hexframe`, `writeTree` to an absolute path, `useradd` and `setpriv` in the image, and the SIGINT are the SDK's types and the image's likely tools read, not behaviour seen; a missing tool fails `ensure` loudly rather than leave the folder writable; the phase close lists them for the first pass with a workspace.

Mapping's `placesOf` answers each Tile's folder and file in the export of its Root, by the names in force where it stands now, and `systemFiles` answers the files and the places from one read, so a Turn's working folder never comes from another read than its files. Assistant owns the sandbox, a Turn's (STACK.md, "Turn"), so the API layer hands Mapping's files to Assistant's `writeSystem` (`api/assistant/programs.ts`, `systemInSandbox`) rather than reaching the repository, from which it takes nothing but plumbing.

### DEC-11 A Turn's Key is IAM's own table, read by its shape; the Turn's one-at-a-time is an index, not a Decider; the Entitlement is an allowlist beside Better Auth

HEX-81. The ticket left the Turn's Key's keeper to the unit, Better Auth's api-key plugin with an expiry and metadata, or IAM's own token, and the Entitlement's env var's name. Five choices followed.

- **IAM's own `turn_key` table, not the plugin.** A Turn's Key lives fifteen minutes, where the plugin's expiry counts in days; it is bound to a Conversation and a Turn, which the plugin keeps only as JSON metadata; and it must never be listed among the Account's Keys, nor need a Session to be revoked, where the plugin lists every key a user has and deletes one through the request's session. A table of IAM's, through the turn-keys repository over `Database`, keeps the binding typed, the listing apart by construction, and joins the transaction that starts or ends the Turn, so a Turn and its Key are written and revoked together. The secret is `hft_` and 32 random bytes in base64url, kept as its SHA-256 alone, as Better Auth keeps a Key's: a random secret needs no salt.
- **Read by its shape.** `keyProven` sends a Bearer secret starting `hft_` to the turn-keys repository alone, by its hash, unexpired by IAM's clock, and any other to Better Auth, so neither keeper is asked about the other's, and an expired Turn's Key never reaches Better Auth's logs as an invalid key. A Key's proof became `{ account, by }`, `by` the same `Proof` `signedIn` answers, a `TurnKey` carrying its Conversation and Turn, so the bus's envelope and a later door read the Turn from it.
- **Its secret is redacted.** `issueTurnKey` answers it as Effect's `Redacted`, so a log or a JSON of what `startTurn` answers never shows it; only the code that starts the Turn unwraps it, for the sandbox's environment and the MCP client's config (HEX-83).
- **One Turn at a time is the table's index.** A partial unique index on `turn (conversation_id) WHERE ended_at IS NULL`, and an insert that does nothing on its conflict, refuse a second running Turn, two started at once included, without a lock; Assistant turns the empty answer into `TurnRunning`. Assistant has no Operations nor Decider yet: the rule needs no state Assistant decides on, and the Mode and the Proposal will bring them. `startTurn` and `endTurn` are programs of the API layer and no server function, since a Turn's Key's secret must never reach a browser; HEX-83 calls them.
- **`ASSISTANT_ACCOUNTS`, an allowlist beside Better Auth.** The `assistant` Entitlement is IAM's (`entitled`, `entitledOnly`, `EntitlementMissing`), derived when asked from `repositories/auth/allowlist.ts`, which reads the comma-separated emails, compared trimmed and case-insensitively, and stands where Stripe's plugin will. The composer reads it through `assistantAvailable` and says, beside its button, that the Assistant isn't available on the Account and its Messages are kept. `vitest.config.ts` pins the list to `entitled@example.com`, whatever the shell exports.

### DEC-12 The model proxy: Assistant admits a call as a value, the settings name its fields and betas from what Claude Code sends, a call reserves its most and waits for those under way, a limit answers 402

HEX-82. The ticket asked for the door a Turn's Claude Code reaches the model through, the relay behind it, Assistant's spending decision and the metering. Eight choices followed, and one thing was not seen.

- **Where it sits.** The door is `api/server/proxy/`, beside `mcp/`, since `api/server/` held its six files and `api/assistant/` its six too; the route is `front/routes/assistant/anthropic.$.ts`, so the agent's base URL is `<origin>/assistant/anthropic` and its path after it the splat. The program composing IAM and Assistant is `modelCall` in `api/assistant/programs.ts`. Assistant's part is a concept folder, `domains/assistant/spending/`, since its own folder held five files: `call.ts`, the schema, and `limits.ts`, the prices and the limits, both pure. The relay is `repositories/agent/anthropic/`, as DEC-10 kept a place for it. `bearerOnly`, what a door a Key opens passes on of its request, moved from `mcp.ts` to `run.ts`, which both doors share.
- **Assistant admits a call as a value, not an error.** `admitCall` answers an `Admission`, `Refused`, `TurnOver`, `Limited` or `Admitted`, rather than errors joining `Failure`: no client of the app ever reads them, and the door words each as Anthropic would, a status and `{ type: 'error', error: { type, message } }`. On a limit Assistant ends its own Turn, by that limit, and the API layer revokes the Key in the same transaction. A Turn's Key is proven by IAM's new `turnOnly`, so an Account's Key reads as nobody at the proxy (401) without a new error either.
- **The settings name the fields; the schema gives each its shape.** `settings.model.fields` lists them, and `call.ts` types its record of shapes by that list, so the compiler refuses a field named without a shape or a shape for a field not named. The body is decoded with `onExcessProperty: 'error'`, which holds at every depth: an unnamed field inside `thinking` is refused as `mcp_servers` is. A tool is a client tool alone, `type` absent or `custom`; a message's content blocks are checked by their type alone, text, image, document, tool use and result, thinking, so no server tool's block passes, their other fields kept as they came since they are the model's to read. The body is read as text and decoded by Assistant, so a body no JSON and one past `largestCall` (32 MB, Anthropic's own limit) are Assistant's refusals too, as is an `anthropic-version` that is no date. The schema speaks Anthropic's words, where the rest of Assistant does not: what an agent may ask the model is a rule on the call as it is relayed, unchanged, and translating it into words of Assistant's own would only be translated back.
- **The betas come from a capture.** Claude Code 2.1.294 was run once, `claude -p "say hi"` with its base URL on a stand-in for Anthropic on this machine (no key, nothing reached Anthropic), to see what it sends. By default it names eleven betas and adds a `safeguards` field for its auto mode's classifier, billed on the platform's key: both refused. With `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` it names four, `claude-code-20250219`, `interleaved-thinking-2025-05-14`, `mid-conversation-system-2026-04-07` and `effort-2025-11-24`, and its body holds only fields the settings name: that call passes the schema as it is. So the Turn (HEX-83) sets that variable, and `settings.model.betas` names those four and a few more that change neither what the model reaches nor its price; `fallbacks`, `speed`, `container`, `mcp_servers`, server tools and fast mode stay out.
- **`max_tokens` is capped, not refused.** Claude Code asks for 128,000; a call asking for more than `settings.model.maxTokens`, 32,000, is sent asking for 32,000, so a Turn runs instead of failing on its first call. A thinking budget at or past the cap is brought to just below it, as Anthropic requires.
- **The limits.** A Turn's ceiling, $1, and an Account's monthly allowance, $10, are settings, in millionths of a dollar like `turn.spent`. The month is the calendar month in UTC, and its spend the sum of `spent` over the Account's Turns started since its first instant (`Turns.spending`), never a counter. A call is checked before it goes, the ceiling first, in a transaction holding the Turn's row: once a Turn's spend is at a limit the call is held back, the Turn ends `ceiling` or `allowance`, its Key revoked with it, and the agent reads a 402 `billing_error`, which Claude Code does not retry. The Turn's row is lock enough for the month too: one Turn runs at a time in an Account's Conversation, and a call of a Turn that is not running is refused, so no two admissions of one Account race.
- **A call reserves the most it may cost, waits for the calls under way, and settles once its answer ended.** cubic's reviews found that checking alone let calls made at once all pass the same check, that a reservation of output alone left their inputs unbounded, and that an answer cut short was charged only what it said until the cut, so an agent could stream and cancel to spend for free. So a call admitted reserves, in the same transaction as its check and on the locked row, no more input tokens than its body has characters at the dearest input price (an hour's cache write) and its `max_tokens` of output, kept apart from what was spent in a column of its own, `turn.reserved` (migration `turn-reserved`), so the limits still end a Turn only by what it spent. A call that would pass a limit with what the calls under way reserved waits for them: the agent reads a 429 `rate_limit_error` with `retry-after: 2`, which Claude Code retries, and the Turn goes on. A call with none under way never waits, however much it reserves, so a Turn below its limits always makes progress, and passes a limit by one call's charge at most. Once its answer has ended, the call settles in a transaction of its own: what it reserved released, what it is charged spent. An answer that came whole, to its `message_stop`, is charged what it used; one cut short, by a Stop, a cancel or upstream, the output it may have answered, since what it used past the cut is not said; one Anthropic refused, nothing; and a call the relay failed to make releases what it reserved at once.
- **How a call is metered.** The relay pulls Anthropic's answer one chunk at a time as the agent reads it and reads its usage on the way, `message_start` then the cumulative `message_delta`, a count said `null` keeping the one before, or a plain answer's `usage`; Assistant prices it, each kind of token at its model's price in the settings' table (Sonnet 5.5 at $2 and $10 per million, cache writes at 1.25 and 2 times input for five minutes and an hour, reads at 0.1 times, Haiku 4.5 likewise from $1 and $5), rounded up. The settling waits for the answer outside any transaction and opens one only to add, the row locked while it adds, with no `sql` template; the API layer hands it to the platform's `waitUntil` with the services the program had, so the function stays up until it is written, and `Services` now lists `WaitUntil`, which `run` always provided. A cost settles on a Turn that has ended meanwhile too: the call cost it.
- **The fake Anthropic is in the process.** `repositories/agent/anthropic/fake.ts` is the relay over an upstream in this process, which records each call and answers by a handler a test sets; `run.ts` takes it under `pnpm dev` without `ANTHROPIC_API_KEY` and in every test, where `vitest.config.ts` empties the key whatever the shell exports.

Not seen against Anthropic: `ANTHROPIC_API_KEY` is not set where this ran, so the pass by hand (`claude -p "say hi"` through the proxy with a Turn's Key, the spend recorded) did not run. The capture above stood in for Claude Code's side; the pass waits for the first run with a key, once the Turn (HEX-83) gives a Turn's Key a way into a sandbox.

### DEC-13 A Turn runs a Node launcher that posts each line Claude Code writes; Assistant reads Claude Code's words; a Turn ends by an Entry of its own, by its time once the next starts; the page polls hidden too

HEX-83. The ticket asked for a Turn on every Message: its agent started in the Account's sandbox, its answer and writes in the timeline, followed live, stoppable. Nine choices followed, and one thing was not seen.

- **The script is a Node launcher, and the agent its child.** The ticket asked for a small script posting each event; the sandbox's stop sends its SIGINT to the process the command line became (DEC-10), and a shell pipeline into `curl` would leave that signal on the shell and put the Key on `curl`'s command line. So the command line is `exec node launcher.mjs`: the launcher spawns the agent, hands a SIGINT on to it, reads its standard output line by line, posts each line to the events door in order with the Key from its own environment, and posts `hexframe_exit` once the agent exited. It builds the MCP client's config in memory from that environment and passes it as `--mcp-config`, so no file the sandbox holds carries the Key. Node is assumed on Blaxel's `claude-code` image beside Claude Code; not seen, below.
- **Claude Code's arguments.** `-p --output-format stream-json --verbose`, `--model` the settings' (`settings.turn.model`), `--append-system-prompt-file`, `--strict-mcp-config`, `--disallowedTools Write Edit NotebookEdit WebFetch WebSearch`, `--permission-mode bypassPermissions` for unattended permissions, the process running as the sandbox's own user, `--max-budget-usd` at the ceiling, `--no-session-persistence` since a Turn is never resumed, and the Message last, after `--`, so one opening with a dash is no option. Its environment adds `ANTHROPIC_SMALL_FAST_MODEL` beside `ANTHROPIC_DEFAULT_HAIKU_MODEL`, and `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` as DEC-12 found it needs.
- **Assistant reads Claude Code's words, in a concept folder.** `domains/assistant/agent/` holds the prompt, the launch and the stream's schema, pure, as `spending/` speaks Anthropic's: the stream is a contract with Claude Code, read as it comes. Assistant keeps of it the text of each message (its Messages), the last tool of a message (the step), and the result: `success` by its answer, `error_max_budget_usd` by its ceiling, any other by its sandbox, as is an exit with no result. A line no schema reads is answered 400 and changes nothing. The prompt names the MCP's tools and Help's id, which the API layer hands it: what an agent is told is Assistant's, the System's words are the files'.
- **The step lives on the Turn's row** (`turn.step`, migration `turn-step`), as Assistant encodes it, set by a tool's line, dropped when the agent speaks again or the Turn ends, and answered by the poll with the Turn running. A step is a tool and a detail cut to 200 characters, never a tool's output. A step stays shown while its tool runs, its result not followed: the next text or tool replaces it.
- **The spend is the proxy's.** "Its spend reconciled" reads as: the Turn's spend is what the proxy metered, each call settled once its answer ended (DEC-12); the result's own `total_cost_usd` is the agent's claim and is never written.
- **A bad end is an Entry of its own**, `TurnEnded`, with how it ended, a fifth kind of Entry the timeline tells, written by Assistant's `endTurn` whoever ends the Turn, a Stop, the proxy's limit, the door's result or exit, its time, or an agent that could not start; nothing for an answer, which the agent's Messages tell. Every one revokes the Turn's Key in the transaction that ends it.
- **A lost Turn ends by its time once the next starts.** The Key proves nothing past the deadline, so a launcher killed at its time cannot say so; the poll answers no Turn past its deadline (`liveTurn`), the composer opens again, and the next Message ends it by its time first, its Key revoked and its agent stopped, its Entry dated from its deadline. Nothing ends it eagerly: a read that writes was the other way, and the poll stays a read. Assistant's `startTurn` no longer ends it itself, as HEX-81 had it: `endOverdueTurn` is the caller's, in the same transaction, so the Key is revoked with it (cubic's review).
- **A Stop may land before the agent started**, which starts once the answer has gone. The start then reads the Turn again once the agent runs, and stops it should it have ended meanwhile: the Stop or the start always sees the other. The Assistant names Claude Code's arguments, but not the app's routes: the API layer hands the launch the doors' paths.
- **A Message starts a Turn in the transaction that posts it.** `postMessage` runs `sendMessage`: an Account without the Entitlement keeps its Message with no Turn, as the composer already says; otherwise a center the System does not hold, a spent allowance (`AllowanceSpent`, Assistant's second error, Forbidden) or a Turn running refuse the whole post, nothing posted.
