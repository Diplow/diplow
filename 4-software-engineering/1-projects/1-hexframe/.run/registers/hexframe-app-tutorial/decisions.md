# Decisions

### DEC-1 Help's code becomes the shipped Systems', each by its Root: the repository, Mapping's concept folder and the build's check

HEX-117, [#133](https://github.com/Diplow/diplow/pull/133). The ticket asked that Help and the tutorial share what they share once, "a shipped System, by its root", so every piece that was Help's alone now takes a Root and is named for what it serves: `repositories/shipped/` (was `help/`), `domains/mapping/shipped/` (was `help/`), whose `shippedOf`, `flatShipped`, `findInShipped` and `shippedSystem` replace their Help-only twins, and `scripts/check-shipped.ts` (was `check-help.ts`). Mapping says which Systems it ships: its door names their Roots, `shippedRoots` in `entities/system.ts`, a Root's id its folder's name, and the bundle must hold a folder per Root, which the typecheck holds; the build's check walks the folder of each. So Help's ids and reads are what they were, and a change naming either System is decided on it, owned by none, which `decide` refuses as it refused Help. With the Roots in the door, which the client may import, the API has one server function by Root, `shipped`, where `help` was, and the client one hook, `useShipped(root, language)`, so a third System would be a Root and a folder. The first draft had the bundle's folder list decide the Roots, and a server function and a hand-typed name per System on the client; cubic's first local round on #133 found both. The MCP's reads take Help's ids only, as before: nothing in the project asks an agent to read the tutorial. STACK.md and cubic's domain-design brief, both frozen for this run, still name Mapping's concept folder after Help (STACK.md's `<concept>/` row, `.cubic/domain-design.md`'s "Mapping's `help/`"), two lines for the phase close.

### DEC-2 `HelpReadOnly` becomes `ShippedReadOnly`, one refusal for Help and the tutorial

HEX-117, [#133](https://github.com/Diplow/diplow/pull/133). The ticket left two ways open, an error of the tutorial's own or Help's renamed for both. `decide` refuses every change to a System no Account owns from the System alone, never from its ids, and the tutorial is such a System, so one refusal keeps that rule in one line, where an error of its own would have needed the System to say which one it is, or a second check by id before `decide`. `ShippedReadOnly` (Forbidden) replaces `HelpReadOnly` everywhere: `decide`'s types, the service, the message table and its sentence in both languages, and the MCP's write tools, whose snapshot changed by that sentence alone. Nothing stored the old tag.

### DEC-3 Home's `tutorial` param names the Tile the tutorial is on; `features/help/` becomes `features/shipped/`

HEX-117, [#133](https://github.com/Diplow/diplow/pull/133). `?tutorial=<id>|true` takes the schema of Help's param. With no widget to open, the id says where the tutorial stands, and it alone: the canvas centers that Tile, its Root for `true`, a move on the tutorial's canvas writes the Tile centered there, and the view's `center` stays the System's, empty meanwhile. The first draft let the URL's `center` win over the param and the param follow it, two fields naming one place, which cubic's first local round found. Signed in, the tutorial takes the canvas, read-only (`looking`), and Help's widget open takes it back, which the feature decides and tests (`shippedOnCanvas`); the corner reads the tutorial only while it is there, so home does not download it on every visit. Signed out, home shows Help and ignores the param, since there is no root of the user's to come back to. A Tile the chat names and `/help` give the canvas back with a view of their own, so no Tile of the tutorial stays in the System's view; the corner's way back is HEX-119's, and nothing else on the screen leaves the tutorial yet. `features/` held six folders, so the help feature became the shipped Systems', `features/shipped/`, rather than a seventh folder beside it, and its six files leave the tutorial's steps a regrouping to make.

### DEC-4 The invitation is derived from the Root and from what was said: the naming's change and a navigation say nothing, a Context Tile counts

HEX-118, [#134](https://github.com/Diplow/diplow/pull/134). The ticket asked for the line while "the account's root has no children and its conversation holds nothing", and for its test "gone once a child or a message exists". The Conversation records every change to the System, the pseudo naming the Root included, so right after the dawn it already holds that change, and soon a navigation: read word for word, the line would never show. So "nothing" is read as the test reads it, nothing said: no Message among the Entries read, by either voice, nor one the user sent on its way or refused, so the line goes the moment a Message is sent rather than once it lands. "No children" is Mapping's `holdsNothing`, from its door: nothing below the Root, a Context Tile included, a rule the domain says once, where Children alone would have been a second copy of it in the front. The Root must be named too, or the line would show while the pseudo is still asked. The Conversation is read a day at a time, and the condition reads the days the page holds (`invitesTutorial`, `features/conversation/invitation/`, a folder of its own, so the timeline's model stays Assistant's alone, as cubic's second local round on #134 asked): a new account that comes back another day, nothing said, is still invited, and one that talked to the agent on a day not read yet, nothing below its Root, would be invited too, which reading every day for one line would cost more than it saves. While the tutorial has the canvas the line stays, as derived: what the chat lets through there is HEX-119's, its "one place that says, from the view, what the tutorial lets through".

### DEC-5 `/tutorial` sets the tutorial's param on its Root, a command run as `/keys` is, and the line names it in the user's amber

HEX-118, [#134](https://github.com/Diplow/diplow/pull/134). `/tutorial` (`/tutoriel` in French, as `/help` is `/aide`; only the language answers to its name in every language) is offered wherever the route gives `onTutorial`, which is home signed in. It sets HEX-117's param to `true`, the tutorial's Root, closes Help's widget, since Help open takes the canvas first (`shippedOnCanvas`), and sets the System's view and change aside as `/help` does, a form open closing with them; on a phone it turns the canvas to the front and keeps it there (`turn`, not a crossing's glance), since the user asked to go there and nothing of the tutorial shows in the chat yet. The words after it are a Message sent once it ran, as after `/keys`, never dropped. While the line invites it, `offered` lists it first (`invited`), so a `/` puts its group first and it first in its group. The line is one `Message` in the agent's voice, its words written once beside the commands (`tutorialInvitation`, which names the command from its own entry), so home, the onboarding slide and the Message's specimen say the same sentence; its command is a fourth kind of `Word` (`ui/chat/text/words.tsx`), a button in the human's amber, as the composer marks a command typed, since it is the user's to run, which a click runs and a copy leaves alone. Typed or clicked, it runs the route's one action. The first draft built the sentence at each place, and the route read the tile widgets' receipt for the dawn; cubic's first local round on #134 found both.

### DEC-6 The invitation rises fifth of the dawn, through `Dawn`, which the receipt shares, and its line clips it only while it rises

HEX-118, [#134](https://github.com/Diplow/diplow/pull/134). The pseudo's receipt rises third of a new account's dawn and the composer fourth; the invitation takes the fifth (`Message`'s `dawning`), so home and the onboarding slide play the same beat. The chat's two beats, and how a line rises within its own line, are one atom, `Dawn` (`ui/chat/atoms/dawn.tsx`), which the receipt rises through too; the first draft wrote the rise twice, with its multiplier in each, which cubic's second local round on #134 found. It dawns only under the pseudo's receipt, which exists only right after the naming, so a reload shows the line at once. Its line clips it while it rises, the conversation sitting on the screen's foot until the composer has risen, but only until its animation ends, and never under reduced motion: the agent's line is reached by the keyboard, and its outline would be cut for as long as the receipt shows. The receipt's clip, which never lifted, now lifts the same way. On `/design-system` the slide plays on into the line, and its `/tutorial` says in a toast what it does on home, the journey there being HEX-119's.

### DEC-7 The journey is a canvas layout keyed by the System shown, the one left receding still drawn, Help counted as home

HEX-119, [#136](https://github.com/Diplow/diplow/pull/136). The camera flies within one System (`useCamera`), and home draws the user's System and a shipped one with two different canvases, so a flight could not cross between them. The journey is a layout of its own around the canvas side, `Journey` (`ui/canvas/layouts/`), which takes the System it shows as a key: when it changes, the drawing last painted stays, keyed by the System left, inert and aria-hidden, and recedes (`animate-recede`), while the one reached comes close (`animate-approach`), both for `--duration-journey`, a new token, 1.8s, longer than a dawn's beat since it crosses more than a level; with reduced motion `movingFor` answers 0 and nothing recedes, a cut. Keeping the last drawing as React nodes, rather than a snapshot, keeps the instance it holds as it goes, so the user's sun recedes as it was, opened or folded. Home keys it `tutorial` or `home`: Help opens over the user's System as a widget's page, not as a place reached, so it keeps its swap and only the tutorial is a journey. The tutorial's read is not fetched ahead: it lands within the journey's first half on the local server, the arriving canvas a skeleton until then.

### DEC-8 The tutorial's rules are one pure function of the view, in `features/shipped/tutorial/`, which the canvas reads as `lets` and the chat as the composer held back

HEX-119, [#136](https://github.com/Diplow/diplow/pull/136). `tutorialRules(view)` answers the view the tutorial shows, the one asked for less what it has not introduced, and what it lets through, in the shape the canvas and the chat take it: the menus (`looking`), each Tile's click and moving the center (`lets`), the composer; a Context is introduced by no step of the project, so none shows. At its arrival, its one step for now, it lets nothing through, so a link naming a child, a ring, an open Branch or a Context shows the center alone too, as `/tutorial` does; each later step adds a case and lifts what it introduces. `shippedOnCanvas` applies it, so the route reads one answer for the canvas and the chat: `ShippedCanvas` hands the canvas its `lets`, which `useCanvasState` holds to (a Tile whose click is held is no button and takes no focus, and where moving the center is held, `recenter`, it moves nowhere, by a click that would center, a double click, Shift+Enter, Go in, Show its Context or Back out), and drops `looking` while menus are held, and the screen's `composerAway` holds the composer back as the onboarding does. `features/shipped/` held six files, so the rules took a folder of their own, `tutorial/`, where the tutorial's later steps will sit too; nothing moved. A canvas the route gives no `lets` lets every gesture through, so Help and the user's System are unchanged. `/design-system`'s onboarding slide reads the same rules, which the route hands it whole, since `ui/` can't reach the feature. The first draft copied them into the slide, let the menu's Show its Context and Back out and a centering click past a held going in, and turned the rules into the canvas's props in two places, which cubic's first two local rounds on [#136](https://github.com/Diplow/diplow/pull/136) found; the flag `goIn` became `recenter`, which says all it holds. Which shipped System is away from home, the tutorial, `shippedOnCanvas` says once (`away`), and the route keys the journey and the way back by it.

### DEC-9 The way back is the Rail's mark, a button wherever its caller gives `onHome`; the chat's other ways out stay as they were

HEX-119, [#136](https://github.com/Diplow/diplow/pull/136). The Sunstone at the head of the corner was an image; given `onHome`, the `Rail` draws it as a button, "Back to your system", which the tutorial's breadcrumb gives and the onboarding slide's too: it sets the tutorial's param aside with the System's view, so the canvas journeys back to the user's Root alone and large, and the composer rises again as the rules no longer hold it. On the user's own System the mark stays hexframe's alone, since nothing there leads back further. A Tile the chat names, the pseudo's receipt included, still takes the canvas from the tutorial (DEC-3), and the invitation's line stays while it is derived (DEC-4): a click on it from the user's System journeys there again, to the tutorial's Root, and from inside the tutorial sets it back on its Root, as the ticket's "arriving again" asks, no progress kept.

### DEC-10 The center's words play on their own, a beat every `--stagger-beat`, one clock for both sides, as long with reduced motion

HEX-120, [#137](https://github.com/Diplow/diplow/pull/137). The project left open whether title, preview and body play on their own or one per click ("To grill"). At the arrival nothing answers a click (DEC-8), and the ticket has the beats play "whenever the center is shown alone", so they play on their own: one every `--stagger-beat`, a new token, 2s, a little longer than the journey, so the first comes once the center has arrived and each leaves time to look at what is lit. The clock is one hook, `useBeats` (`ui/motion.ts`, beside the durations, since both sides read it), which the route calls once and hands the canvas and the chat, so the light and the words can't drift apart; `/design-system`'s onboarding slide calls it the same way. It starts once the tutorial is read, since a beat with nothing drawn would be lost, and from the start again each time the tutorial arrives anew; staying on the arrival, `/tutorial` again replays nothing, no progress kept either way. What it plays is the rules' (`tutorialRules`' `tells`, the arrival's), so a later step that opens the center stops it. "Reduced motion shows them without the motion" is read as the beats kept and their motion dropped: a beat lights and says, which `durationOf` times either way, as the flare and the glance are, while the lines rise only `motion-safe` and the light fades only `motion-safe`; showing all three at once would have lost the one thing lit at a time. The body's beat brings the chat to the front on a phone, where the canvas is in front since `/tutorial` (DEC-5); the onboarding slide's screen state is its deck's, so it does not.

### DEC-11 What is lit is a mark, `told`, in the agent's violet; the beats and the body are `Told`, in `Message.tsx`, the numbered list a list by `blocksOf`

HEX-120, [#137](https://github.com/Diplow/diplow/pull/137). A tile's title or preview lit is someone touching the tile, the agent telling of it, so it is a mark (`TileMark`'s `told`, `ui/canvas/tile/marks/`), its body among the parts, which lights nothing on the tile, in the agent's violet as its other marks are, handed through the canvas's `marks` as the chat's pointing is, its `told`, which the canvas puts on the center it draws, so home (`ShippedCanvas`'s `told`) and the slide hand it the part as it is (cubic's second local round on #137 found the center worked out at each), and shown at `/design-system` among the Marks piece's states, played, rather than as a piece of its own. It glows round the words' own shapes by a `drop-shadow` filter, which keeps the words' ink and contrast: a text shadow, the first draft, was cut to a box by the line clamp's overflow, which a browser check showed. The chat's side is `Told`, beside `Message` in `ui/chat/text/Message.tsx`, since the chat's folders and `text/` are full and the beats are three of the agent's Messages and its body: the words are the ticket's, "A title.", "A preview.", "And a body.", in both languages, kept as proposed, and the body is read from the tutorial's Tile, never from messages. Its numbered list is a list in any of the agent's Messages: `blocksOf` (`words.tsx`) gathers the lines opening with a number and a dot into an `<ol>`, its numbers as written, hanging, the rest of Markdown still waiting for the seam's renderer, which a list alone did not justify bringing in; `ui/seams/` names it as the one piece of Markdown read outside the seam until then, which cubic's first local round on [#137](https://github.com/Diplow/diplow/pull/137) asked. The beats' few words sit in `ui/` as the invitation's do (`tutorialInvitation`, DEC-5), so home and the slide say the same; they name a tile's parts, any tile's. The parts, their order and the part reached on the clock are `ui/motion.ts`'s, `ToldPart` and `useTold`, beside `useBeats`, which both sides read, so the canvas's lit part and the chat's beats are one type; the first draft indexed the beats at each, which the same round found. The body told is the Root's: the rules tell only at the arrival, whose center is the Root (DEC-8), and a later step that tells another Tile's words would take its body from the center.
